# mech-interp-uncertainty

Applying a clustered-bootstrap uncertainty methodology — originally built for
forensic firearm examination data — to AI safety evaluation and (as a stretch
goal) mechanistic interpretability.

This repo is a duplicate-with-full-history of
[StatsCOMPSGroup1](https://github.com/panditk455/StatsCOMPSGroup1) (the
Carleton COMPS project, Pandit/Wang/Chang, Spring 2026). The original forensic
work is preserved unchanged in [`forensic_foundation/`](forensic_foundation/)
as the methodological foundation; everything outside that folder is new,
written in Python.

## The core idea

The forensic project's real finding wasn't about firearms — it was about what
happens when observations are generated by **two crossed, non-independent
sources**: examiners and comparison items (csets). Naive bootstrap CIs that
ignore this structure understate uncertainty by 25-35 points; only a two-way
clustered bootstrap (Cameron, Gelbach & Miller 2011) fixes it.

That structure maps directly onto AI safety evaluation:

| Forensic project | AI safety analog |
|---|---|
| Examiner | Model / agent / attack method being evaluated |
| Cset (comparison item) | Benchmark prompt / task |
| Examiner random effect | Model-specific tendency not captured by fixed effects |
| Cset random effect | Item difficulty — some prompts trigger a failure mode regardless of model |
| Inconclusive -> error (two-stage) | Refuse/abstain -> then, if it answers, correct/incorrect |
| Hawthorne effect (examiner knows they're studied) | Evaluation awareness / sandbagging |
| Naive vs. clustered CI coverage gap | The gap most published safety/capability benchmarks currently ignore |

Most LLM safety benchmarks report a point estimate, or a CI that treats every
(model, prompt) pair as independent. `clustered_bootstrap/` is a generic,
domain-agnostic port of the R bootstrap machinery from
`forensic_foundation/simulation_combined/combined_bootstrap.R`, built to make
it trivial to check whether that gap actually matters for a given benchmark.


## Tiers of work

**Tier 1 (usable now):** apply the clustered bootstrap to a real model x
prompt results matrix — an attack-success-rate table, a hallucination
benchmark, etc.

```bash
pip install -r requirements.txt
python -m ai_safety_extension.clustered_bootstrap_evals your_results.csv \
    --model-col model --prompt-col prompt --outcome-col outcome
```

Input is long-format: one row per (model, prompt) observation with a binary
outcome column. See the docstring in
[`ai_safety_extension/clustered_bootstrap_evals.py`](ai_safety_extension/clustered_bootstrap_evals.py)
for the exact schema and an optional two-stage (`--stage1-col`) mode for
refuse-then-error analyses.

**Tier 2 (skeleton, needs live model access):** run models on a benchmark
twice — once with eval-disclosing framing, once framed as ordinary deployment
use — and estimate whether the two-stage (abstain, then error) rates shift.
See [`ai_safety_extension/eval_awareness_experiment.py`](ai_safety_extension/eval_awareness_experiment.py).

**Tier 3 (stretch goal, needs interpretability tooling):** apply the same
clustered bootstrap to interpretability-probe accuracy instead of eval
outcomes. See [`ai_safety_extension/probe_uncertainty/README.md`](ai_safety_extension/probe_uncertainty/README.md).

## Validating the Python port

Before trusting the Python bootstrap on real data, `examples/synthetic_validation.py`
runs the same style of Monte Carlo coverage check as the R forensic simulation
on synthetic two-way-clustered binary data, confirming the qualitative result
holds:

```bash
python -m examples.synthetic_validation
```

```
  method statistic  true_value  coverage_rate  mean_ci_width
     row      rate       0.406           0.48          0.048
cluster1      rate       0.406           0.87          0.133
cluster2      rate       0.406           0.74          0.089
combined      rate       0.406           0.95          0.168
```

Naive (row) coverage collapses well below the nominal 95% target; the combined
bootstrap lands right on it — the same pattern as the forensic paper's headline
finding, on different (synthetic) data.

## Literature to verify before citing formally

Drawn from training knowledge, not a live search — check titles/years/venues:

- Eval statistics: work arguing LLM evals need real error bars rather than
  point estimates; METR's published methodology for autonomous-capability
  evaluations (bootstraps over agent/task structure); prompt-template
  sensitivity studies showing large score variance across paraphrased prompts.
- Eval awareness / sandbagging: Greenblatt et al., "Alignment Faking in Large
  Language Models"; Apollo Research's in-context scheming work.
- Interpretability/probing: Burns et al., "Discovering Latent Knowledge in
  Language Models Without Supervision"; Zou et al., "Representation
  Engineering"; Arditi et al., "Refusal in Language Models Is Mediated by a
  Single Direction"; Templeton et al., "Scaling Monosemanticity".
