# mech-interp-uncertainty

Quantifying uncertainty in AI safety evaluations and mechanistic
interpretability research: does a benchmark score, a probe accuracy, or a
sandbagging effect actually hold up once you account for the fact that results
cluster by both model *and* by prompt/task — not just one or the other, and
not neither?

Most published safety and capability benchmarks report a single number, or a
confidence interval that quietly treats every (model, prompt) pair as
independent. That's usually wrong, and it's checkable: a **two-way clustered
bootstrap** (Cameron, Gelbach & Miller 2011) gives the right interval by
resampling both clustering dimensions and combining them.

## Three directions

**[`benchmark_uncertainty/`](benchmark_uncertainty/)** — working now. Feed it
any real model x prompt eval matrix (attack-success rates, hallucination
rates, whatever) and it returns naive vs. model-cluster vs. prompt-cluster vs.
combined confidence intervals, so you can see directly how much the naive
number was hiding.

```bash
pip install -r requirements.txt
python -m benchmark_uncertainty.clustered_bootstrap_evals your_results.csv \
    --model-col model --prompt-col prompt --outcome-col outcome
```

Input is long-format: one row per (model, prompt) observation with a binary
outcome column. See the docstring in
[`benchmark_uncertainty/clustered_bootstrap_evals.py`](benchmark_uncertainty/clustered_bootstrap_evals.py)
for the exact schema and an optional two-stage (`--stage1-col`) mode for
refuse-then-error analyses.

**First real result:** [`benchmark_uncertainty/fetch_truthfulqa_data.py`](benchmark_uncertainty/fetch_truthfulqa_data.py)
pulls real per-question TruthfulQA-MC1 results for 11 open models (Llama-2 at
7B/13B/70B, both Mistral-7B variants, Falcon-7B/40B, Gemma-7B, Phi-2, Yi-6B,
GPT-J-6B) from HuggingFace's public Open LLM Leaderboard detail logs — no
inference run needed, all free. Across 8,987 (model, question) observations,
the naive bootstrap says the hallucination rate is known to within
**70.8%-72.6%** (width 1.8 points); accounting for both model- and
question-clustering, the true 95% interval is **67.7%-75.9%** (width 8.1
points) — the naive interval understates the uncertainty by about 4.5x. Data
in `benchmark_uncertainty/data/truthfulqa_mc1.csv`, result in
`benchmark_uncertainty/data/truthfulqa_mc1_bootstrap_result.txt`.

**[`eval_awareness/`](eval_awareness/)** — implemented, not yet run. Does a
model behave differently when it can tell it's being evaluated versus
deployed? `experiment.py` asks each of Groq's current models (`openai/gpt-oss-20b`,
`openai/gpt-oss-120b`, `qwen/qwen3.6-27b` — check
[console.groq.com/docs/models](https://console.groq.com/docs/models), their
catalog changes) the same TruthfulQA multiple-choice question twice — once
under an eval-disclosing system prompt, once under an ordinary-deployment one
— then compares abstention and error rates across conditions with the
clustered bootstrap (model x question). Connects directly to sandbagging and
alignment-faking findings. Needs a free API key from console.groq.com set as
`GROQ_API_KEY`, then:

```bash
python -m eval_awareness.experiment --n-questions 60
```

**[`probe_uncertainty/`](probe_uncertainty/)** — early-stage, and the one I'm
most excited about. Interpretability papers train a probe on model
activations (a refusal direction, an "is this being evaluated" feature, a
deception detector) and report one accuracy number with no correction for the
fact that prompts cluster by template and models cluster by checkpoint —
probably the least statistically rigorous corner of eval reporting right now.
Same clustered-bootstrap machinery, applied to probe accuracy instead of eval
outcomes. See [`probe_uncertainty/README.md`](probe_uncertainty/README.md) for
the plan.

## Where the method comes from

The statistical core here — [`clustered_bootstrap/`](clustered_bootstrap/) —
started as the two-way clustered bootstrap built for a Carleton COMPS project
on forensic firearm examiner data
([StatsCOMPSGroup1](https://github.com/panditk455/StatsCOMPSGroup1),
Pandit/Wang/Chang, Spring 2026), preserved unchanged here in
[`forensic_foundation/`](forensic_foundation/). That project's real finding
wasn't about firearms: when observations are generated by two crossed,
non-independent sources (there, examiners x comparison items), naive bootstrap
CIs understate uncertainty by 25-35 points, and only a combined bootstrap
fixes it. That's the same structural problem underneath model x prompt,
model x task, or model x probe-template — which is what made the pivot worth
doing rather than a stretch.

| Forensic project | Here |
|---|---|
| Examiner | Model / agent / attack method |
| Cset (comparison item) | Benchmark prompt / task |
| Examiner random effect | Model-specific tendency not captured by fixed effects |
| Cset random effect | Item difficulty — some prompts trigger a failure mode regardless of model |
| Inconclusive -> error (two-stage) | Refuse/abstain -> then, if it answers, correct/incorrect |
| Hawthorne effect (examiner knows they're studied) | Evaluation awareness / sandbagging |

`clustered_bootstrap/` is a generic, domain-agnostic Python port of the R
bootstrap machinery in `forensic_foundation/simulation_combined/combined_bootstrap.R` —
all three directions above call the same core functions.

```
mech-interp-uncertainty/

├── examples/

├── probe_uncertainty/            # clustered CIs for interpretability probes
└── forensic_foundation/          # the original COMPS project, unchanged (R)
```

## Validating the Python port

Before trusting the bootstrap on real data, `examples/synthetic_validation.py`
runs a Monte Carlo coverage check on synthetic two-way-clustered binary data,
confirming the same qualitative result as the forensic paper holds:

```bash
python -m examples.synthetic_validation
```

```
  method statistic  true_value  coverage_rate  mean_ci_width
     row      rate       0.406           0.48          0.048
cluster1      rate       0.406           0.87          0.133
cluster2      rate       0.406           0.74          0.089
combined      rate       0.406           0.95          0.168
```

Naive (row) coverage collapses well below the nominal 95% target; the combined
bootstrap lands right on it.

## Literature to verify before citing formally

Drawn from training knowledge, not a live search — check titles/years/venues:

- Eval statistics: work arguing LLM evals need real error bars rather than
  point estimates; METR's published methodology for autonomous-capability
  evaluations (bootstraps over agent/task structure); prompt-template
  sensitivity studies showing large score variance across paraphrased prompts.
- Eval awareness / sandbagging: Greenblatt et al., "Alignment Faking in Large
  Language Models"; Apollo Research's in-context scheming work.
- Interpretability/probing: Burns et al., "Discovering Latent Knowledge in
  Language Models Without Supervision"; Zou et al., "Representation
  Engineering"; Arditi et al., "Refusal in Language Models Is Mediated by a
  Single Direction"; Templeton et al., "Scaling Monosemanticity".
